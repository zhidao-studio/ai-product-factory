# 实施任务：[FEATURE NAME]

**需求目录**：`specs/[###-feature-name]/`

**状态**：草稿

**输入**：已确认的 `spec.md` 与 `plan.md`，以及计划中明确需要的附属工件

> 前置门禁：用户已经分别确认需求和计划。本清单不得增加新业务范围，也不得把通用脚手架
> 初始化、无关重构或预建空壳混入 Feature 任务。

## 任务格式

每项任务必须使用以下格式：

`- [ ] T001 [P?] [US-001] [BR-001] [AC-001] 在 <真实文件路径> 完成 <明确结果>；验证：<方法>`

- `[P]` 仅表示任务修改不同文件、无未完成依赖且可安全并行；不满足时省略。
- `[US-xxx]` 为业务实现任务必填；纯共享前置或最终验证可写 `[SHARED]`。
- `[BR-xxx]` 与 `[AC-xxx]` 按实际追踪填写，可列多个，但不得填写无关编号凑数。
- 描述必须包含真实文件路径、可观察交付结果和验证方式，禁止“处理后端”“完善页面”等模糊任务。

## 任务确认

- **状态**：待用户确认
- **确认人**：[由用户或其明确指定的实施评审人填写]
- **确认依据**：[记录确认所在的任务、评审或链接]
- **确认内容**：任务范围、US/BR/AC 追踪、依赖、精确路径与验证方式
- **实施门禁**：确认任务后必须先运行 `$speckit-analyze`；解决或明确接受所有 CRITICAL/HIGH
