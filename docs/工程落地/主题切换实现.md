# 主题切换实现

> 基于 antd 5.x ThemeConfig，实现亮色/深色/紧凑与品牌换肤的动态切换。

---

## 1. 架构原则

- 所有主题通过 `ConfigProvider` 注入，业务组件零侵入
- 主题配置集中在 `theme.config.ts`（见 [Design Token 架构](Design Token 架构.md)）
- 运行时切换无需刷新；静态方法用 `App` 组件消费 context

---

## 2. 基础配置

```tsx
import { ConfigProvider, theme } from 'antd';

const themeConfig = {
  token: tokens,                    // 来自 Design Token 架构
  algorithm: theme.defaultAlgorithm,
  cssVar: true,                     // 开启 CSS 变量
};
```

---

## 3. 深色模式

```tsx
const darkConfig = {
  algorithm: theme.darkAlgorithm,
  token: { colorPrimary: '#1668DC' },  // 深色提亮
};

// 跟随系统
const mq = window.matchMedia('(prefers-color-scheme: dark)');
```

## 4. 紧凑模式

```tsx
const compactConfig = { algorithm: theme.compactAlgorithm };
// 组合：深色 + 紧凑
const darkCompact = { algorithm: [theme.darkAlgorithm, theme.compactAlgorithm] };
```

---

## 5. 全局主题 Provider（推荐结构）

```tsx
// App.tsx
function App() {
  const [mode, setMode] = useState<'light'|'dark'>('light');
  const algo = mode === 'dark' ? theme.darkAlgorithm : theme.defaultAlgorithm;
  return (
    <ConfigProvider theme={{ token: tokens, algorithm: algo, cssVar: true }}>
      <AntdApp>            {/* App 组件解决静态方法 context */}
        <Router />
      </AntdApp>
    </ConfigProvider>
  );
}
```

> ⚠️ `message.xxx` / `Modal.xxx` 静态调用不吃 ConfigProvider，改用 `App.useApp()` 返回的实例。

---

## 6. 动态换肤

```tsx
// 主题切换组件
function ThemeSwitcher() {
  const { theme: setTheme } = theme.useToken(); // 取当前
  const changePrimary = (c: string) =>
    setTheme({ token: { colorPrimary: c } });   // 局部/全局改主色
}
```

---

## 7. 移动端（antd-mobile）

```css
:root:root { --adm-color-primary: #1677FF; }
/* 深色由 CSS 媒体查询或 JS 切换 class */
[data-theme='dark'] { --adm-color-primary: #1668DC; }
```

---

## 8. 持久化

- 主题偏好存 `localStorage`，启动时读取
- 首次访问跟随系统 `prefers-color-scheme`
- 提供手动切换入口（设置页）

---

## 9. 规则

- ✅ 主题切换必须走 ConfigProvider，禁止全局改 CSS
- ✅ 静态方法用 `App` 组件，避免 context 丢失
- ❌ 禁止每页重复 ConfigProvider（仅根一次，子页用嵌套局部）
