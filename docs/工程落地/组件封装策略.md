# 组件封装策略

> 在 antd 基础组件之上，封装业务组件，统一团队用法、降低重复。

> **适用性说明：本文的“独立发包”是通用建议，不适用于本仓库五端共享。** 每个前端只能在本工程内封装组件，不得让其他端运行时依赖该包；跨端只统一设计语义和后端契约。

---

## 1. 封装层级

```
antd 基础组件
   ↑
业务通用组件（SearchBar / FilterForm / DataTable / PageHeader）
   ↑
页面（组合业务组件）
```

- **不修改 antd 源码**，仅组合/扩展
- 业务组件库独立发包（见 [monorepo 与包管理](monorepo 与包管理.md)）

---

## 2. 封装原则

1. **透传 props**：不截断 antd 原生 API（`...rest`）
2. **收敛默认值**：业务通用默认值（如分页 20 条）在封装层统一
3. **语义化命名**：`DataTable` 而非 `MyTable`
4. **样式走 Token**：用 `useToken()` 取色，禁止硬编码
5. **受控优先**：状态外提，组件纯净

---

## 3. 典型业务组件

| 组件 | 基于 | 封装内容 |
|---|---|---|
| `PageHeader` | Typography + Button | 标题 + 返回 + 操作区统一 |
| `SearchBar` | Form(inline) + Button | 查询/重置 + 折叠高级 |
| `DataTable` | Table + Pagination | 默认密度/分页/空态/加载 |
| `FilterForm` | Form | 栅格筛选 + 值收集 |
| `ProDrawerForm` | Drawer + Form | 编辑表单抽屉封装 |
| `StatusTag` | Tag | 状态→颜色映射表 |

---

## 4. 示例：DataTable

```tsx
interface Props extends TableProps {
  // 仅扩展业务默认，其余透传 antd
}
function DataTable({ pagination, ...rest }: Props) {
  const { token } = theme.useToken();
  return (
    <Table
      pagination={{ pageSize: 20, showSizeChanger: true, ...pagination }}
      scroll={{ x: 'max-content' }}
      {...rest}
    />
  );
}
```

## 5. 状态映射（StatusTag）

```ts
const STATUS_MAP = {
  success: { color: 'success', text: '已完成' },
  processing: { color: 'processing', text: '进行中' },
  error: { color: 'error', text: '失败' },
};
// 全团队复用，避免各处手写颜色
```

## 6. 移动端封装（antd-mobile）

- `ListForm`：垂直表单 + 底部提交
- `CardList`：Card 包裹 List
- 同原则：透传 + Token + 受控

---

## 7. 规则

- ✅ 业务组件独立仓库/包，版本管理
- ✅ 业务组件测试覆盖（交互/状态）
- ❌ 在业务页面重复写相同组合（应提为组件）
- ❌ 封装层硬编码颜色/间距
