# 命名规范

> 统一命名是设计与开发协作的隐形契约。覆盖 Token、组件、图层、文件、变量。

---

## 1. Design Token 命名

格式：`维度 + 语义 + 修饰`

```
colorPrimary
colorPrimaryHover
colorTextSecondary
colorBgContainer
borderRadiusLG
marginLG
fontSizeHeading3
boxShadowTertiary
```
- 驼峰（camelCase）
- 颜色：`color` 前缀；语义色用功能名（Primary/Success/...）
- 间距/圆角：`margin/padding/borderRadius` + 梯度（XXS~XXL）

---

## 2. 组件命名

```
Button / Input / Table / Modal ...（与 antd 一致）
```
- 首字母大写，与 antd 组件名对齐（降低沟通成本）
- 业务组件：语义化，如 `DataTable` / `SearchBar`（见 [组件封装策略](../工程落地/组件封装策略.md)）

---

## 3. 图标命名

```
icon-{类别}-{动作}
icon-action-edit
icon-nav-back
icon-status-success
```
- 前缀 `icon-`，kebab-case
- 同时交付 outlined / filled

---

## 4. Figma 图层命名

```
[组件]/[变体]/[状态]
Button/Primary/Large
ListItem/Selected
Modal/Confirm
```
- 组用 `/` 分层
- 禁用「矩形 12」「副本 3」之类默认名

---

## 5. 文件命名

```
页面：{模块}-{页面}  如 user-list / user-detail
分支：feature/xxx / fix/xxx
```
- 小写 kebab-case
- 设计稿文件名与路由/页面一致

---

## 6. 变量（代码）命名

```ts
// 布尔
const isLoading / hasError / visible
// 事件
onSubmit / onChange / onConfirm
// 组件 props 对齐 antd
```

---

## 7. 规则

- ✅ 一切命名对齐 antd，减少翻译成本
- ✅ Token 命名与 `packages/tokens` 文件一致
- ❌ 中文/拼音命名（代码与 Token 禁中文）
