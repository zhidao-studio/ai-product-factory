# 版本与变更管理

> 设计系统随业务演进，但必须可控。任何破坏性变更需评审与通知。

---

## 1. 版本号（语义化）

`MAJOR.MINOR.PATCH`

| 级别 | 触发 |
|---|---|
| **MAJOR** | 破坏性：Token 改名/移除、组件 API 删除、栅格重构、主色变更 |
| **MINOR** | 新增：新组件/新变体/新平台支持，向后兼容 |
| **PATCH** | 修正：文案、示例、非破坏微调 |

---

## 2. 变更流程

```
1. 提案（Issue/PR）
   - 说明变更内容、影响范围、兼容性
2. 评审
   - 设计 + 前端 + 技术负责人评审
   - MAJOR 变更需额外架构评审
3. 实现
   - 改 tokens/组件文档 + Figma + 代码包
   - 更新 CHANGELOG
4. 通知
   - 发版说明 + 迁移指南（MAJOR）
   - 同步团队（IM/文档）
5. 废弃（Deprecation）
   - 旧 API 标记 @deprecated，保留 ≥ 1 个 MINOR 周期
   - 提供替代方案与 Codemod（如可行）
```

---

## 3. 破坏性变更管理

- 必须提供迁移指南（before/after 代码）
- 旧版本保留 N 个周期后再移除
- 跨包影响：触发消费包 CI 校验
- 通知所有业务团队升级排期

---

## 4. 新增内容流程

- 先写组件文档（[组件库](../组件库/组件总览.md)）→ 再建 Figma → 再发包
- 文档 + Figma + 代码三者一致后方可 MINOR 发版

---

## 5. Token 变更

- 改 `packages/tokens` 单一来源
- 触发 Figma 同步（Tokens Studio）
- 消费包 CI 比对，防止硬编码漂移

---

## 6. CHANGELOG 模板

```
## 1.3.0 (2026-09-01)
### Added
- 新增 Statistic 数值组件
### Changed
- Table 默认行高 48→44 (兼容性: 不影响 API)
### Breaking
- colorTextBase 移除（迁移: 改用 colorText）
```

---

## 7. 工具

- Changesets（版本 + CHANGELOG 自动）
- Figma Versions（设计版本）
- 文档站版本切换（保留历史版本文档）

---

## 8. 规则

- ✅ 每次发版升级版本号 + 写 CHANGELOG
- ✅ MAJOR 变更必附迁移指南
- ❌ 静默改 Token 名（所有消费方编译失败）
- ❌ 跳过评审直接改基础组件 API
