# 错误与文案体系

> 模块：UX 交互 ｜ 关联：反馈机制、异常与空状态、无障碍设计
> 核心：**错误不是系统的失败，而是帮用户成功的机会**。文案决定用户是"骂街"还是"照做"。

---

## 1. 错误分级

| 级别 | 表现 | 示例 |
|---|---|---|
| 阻断级（Blocker） | Modal / Result 错误页 | 支付失败、无网络无法继续 |
| 字段级（Field） | 表单下方红字 | 手机号格式错误 |
| 提示级（Toast） | 轻提示自动消失 | 操作失败，请重试 |
| 静默级（Inline） | 内联状态 | 自动保存失败，已重试 |

---

## 2. 文案写作原则（黄金法则）

1. **说人话**：不用技术术语（不说"500 Internal Error"，说"服务开了小差，稍后重试"）。
2. **指出原因**：用户做错了什么（"密码长度至少 8 位"）。
3. **给出下一步**：必须带可执行动作（"重新上传" / "返回上一步"）。
4. **不怪用户**：用"我们"而非"你错了"（"我们无法连接，请检查网络"）。
5. **一致语气**：全局统一温和、专业，不卖萌不恐吓。

---

## 3. 标准文案模板

| 场景 | 推荐文案 | 禁用文案 |
|---|---|---|
| 网络错误 | 网络连接失败，请检查后重试 | 网络错误 |
| 加载失败 | 内容加载失败，点击重试 | 加载失败 |
| 表单校验 | 请输入有效的手机号 | 输入有误 |
| 无权限 | 你没有访问该页面的权限 | 无权限 |
| 操作成功 | 已保存 | 成功 |
| 删除确认 | 删除后不可恢复，确定继续？ | 确定删除？ |
| 404 | 页面走丢了，返回首页 | 404 Not Found |
| 服务器错误 | 服务暂时不可用，请稍后再试 | 500 Error |

---

## 4. 错误码与映射（开发约定）

- 业务错误码统一管理（如 `ORDER_NOT_FOUND`、`AUTH_EXPIRED`）。
- 前端维护 `errorCode → 用户文案` 映射表，**文案只在此处**，不散落业务代码。
- 未知错误兜底文案："出了点问题，请稍后重试"（不暴露原始堆栈）。

```ts
// errors.ts
export const ERROR_MESSAGES: Record<string, string> = {
  NETWORK_ERROR: '网络连接失败，请检查后重试',
  ORDER_NOT_FOUND: '订单不存在或已被删除',
  AUTH_EXPIRED: '登录已过期，请重新登录',
  // ...
};
```

---

## 5. 无障碍文案

- 错误提示须与输入框 `aria-describedby` / `role="alert"` 关联，读屏可播报。
- 颜色不单独承载含义：错误除红色外必须有文字/图标说明（色盲可见）。

---

## 6. 反模式

- ❌ 只写"错误"二字无指引
- ❌ 暴露技术堆栈/错误码给用户
- ❌ 文案散落各处无统一映射
- ❌ 仅用颜色表示错误（色盲不可见）
- ❌ 怪罪用户（"你输错了"）

---

## 7. 自检

- [ ] 错误分级正确（阻断/字段/提示/静默）
- [ ] 文案含原因 + 下一步
- [ ] 有统一 errorCode→文案映射
- [ ] 未知错误有兜底
- [ ] 错误有读屏关联、非仅颜色
