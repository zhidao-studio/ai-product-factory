# 加载与骨架屏策略

> 模块：UX 交互 ｜ 关联：反馈机制、动效系统、组件库/反馈/Spin
> 核心原则：**永远不要让用户面对空白或"假死"**。加载态要传达"系统在工作、内容即将到来"。

---

## 1. 三种加载态的选择

| 场景 | 用 | 不用 |
|---|---|---|
| 整页/区块首次加载 | **骨架屏 Skeleton** | 整页 spinner |
| 局部刷新/提交 | 按钮 loading / 内联 spinner | 全屏遮罩 |
| 触底加载更多 | 列表底部 spinner + "加载中" | 弹 Toast |
| 后台静默刷新 | 极轻量顶部进度条（如 1px 渐变条） | 任何遮挡 |
| 瞬时操作（<300ms） | 无需指示 | 反而拖慢感知 |

---

## 2. 骨架屏（Skeleton）规范

- **形状贴合**：占位块的形状/尺寸/间距必须贴近真实内容（标题行、图片方块、按钮位），让用户"预感"布局。
- **颜色**：`colorBgLayout` 底色 + 微光扫过动画（`shimmer`，用 `gradient` 位移，时长 1.2~1.5s，缓动 `easeInOut`）。
- **节奏**：骨架出现 ≤ 100ms；若数据 < 300ms 返回，跳过骨架直接渲染（避免"闪一下"更糟）。
- **层级**：骨架层级 = 被替代内容的层级，不压过导航。
- **结束**：内容淡入（`durationSmall` 200ms），非生切。

```tsx
<Skeleton active paragraph={{ rows: 3 }} title avatar />
// 或自定义：用 CSS shimmer 覆盖真实结构的占位 div
```

---

## 3. 进度指示

| 类型 | 用途 | 规范 |
|---|---|---|
| 按钮 loading | 提交/保存 | 右置 spinner，禁用防重复点击 |
| 内联 spinner | 局部刷新 | 直径 16~20px，色 `colorPrimary` |
| 顶部进度条 | 路由/静默加载 | 高度 2~3px，`colorPrimary`，不确定动画 |
| 环形 Progress | 可量化任务 | 显示百分比（上传/导出） |

---

## 4. 乐观更新（Optimistic UI）

- 适用：点赞、收藏、开关等低风险的即时反馈操作。
- 做法：先本地更新 UI + 轻提示，再发请求；失败则回滚 + 错误提示。
- 禁止：涉及资金、权限、删除等不可逆操作使用乐观更新。

---

## 5. 超时与失败

- 超时（如 10s 无响应）：转为错误态，提供"重试"按钮，不无限转圈。
- 失败：用 `Result` 或 `Empty` 的 error 变体，文案具体（"网络异常，请检查后重试"），禁止"加载失败"三无文案。

---

## 6. 反模式

- ❌ 整页 spinner 代替骨架（用户不知布局）
- ❌ 骨架闪烁（<300ms 仍显示）
- ❌ 删除等危险操作用乐观更新
- ❌ 无限加载无超时
- ❌ 失败时"加载失败"无重试

---

## 7. 自检

- [ ] 首屏用骨架而非空白/spinner
- [ ] 骨架形状贴合真实布局
- [ ] 局部用内联 loading，不遮挡
- [ ] 有超时 + 重试
- [ ] 危险操作无乐观更新
