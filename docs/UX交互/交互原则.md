# 交互原则

> UX 交互的底层准则，约束所有页面与组件的交互设计。

---

## 1. 四大体验原则

| 原则 | 含义 | 落地 |
|---|---|---|
| 清晰 | 内容优先 | 每屏一个重点 |
| 一致 | 降低学习 | 同功能同组件 |
| 反馈 | 感知操作 | 100ms 内反馈 |
| 效率 | 减少操作 | 优先选择 |

详见 [设计原则](../基础规范/设计原则.md)。

---

## 2. 操作反馈

| 操作 | 反馈 | 延迟 |
|---|---|---|
| 按钮点击 | 颜色/缩放 | < 100ms |
| 表单提交 | Loading | < 100ms |
| 数据加载 | Skeleton/Spinner | < 300ms |
| 成功 | Toast | 完成即显 |
| 失败 | 错误+方案 | 完成即显 |

---

## 3. 操作确认

| 场景 | 方式 |
|---|---|
| 不可逆（删除） | Modal 确认 |
| 重要（支付） | 确认 + 二次 |
| 一般（保存） | 直接执行 |
| 离开未保存 | 系统提示 |

---

## 4. 撤销优于确认

- 删除显 Toast + 「撤销」按钮（5~10s 窗口）
- 比 Modal 确认更轻量、不打断

---

## 5. 容错

- 输入即时校验（手机号格式）
- 提交前可取消
- 错误明确告知原因与解法

---

## 6. 渐进披露

- 高级功能收起（「高级筛选」）
- 不一次性暴露所有控件

---

## 7. 规则

- ✅ 每个操作有反馈
- ✅ 不可逆操作有确认或撤销
- ❌ 静默失败
- ❌ 过度弹窗打断流程
