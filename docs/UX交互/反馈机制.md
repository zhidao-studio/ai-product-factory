# 反馈机制

> 每个操作需及时、明确的反馈。区分轻量提示与强阻断。

---

## 1. 反馈类型对照

| 类型 | 组件 | 时长 | 打断 | 场景 |
|---|---|---|---|---|
| 轻提示 | `message`/Toast | 1.5~3s | 否 | 成功/信息 |
| 通知 | `notification` | 4.5s/可关 | 否 | 异步结果 |
| 弹窗 | `Modal` | 用户关 | 是 | 重要确认 |
| 抽屉 | `Drawer` | 用户关 | 是 | 编辑/详情 |
| 气泡 | `Popover`/`Tooltip` | hover | 否 | 辅助说明 |
| 行内 | `Alert` | 持续 | 否 | 页级提示 |
| 徽标 | `Badge` | 持续 | 否 | 数量/状态 |

---

## 2. 文案规范

- 成功：「操作成功」「已保存」「已删除」
- 失败：「保存失败，请重试」「网络异常，请检查」
- 加载：「正在加载…」「正在提交…」
- 空：「暂无数据」「未找到结果」
- 移动端文案 ≤ 一行

---

## 3. 选择原则

- 轻量结果 → Toast（不打断）
- 关键错误 → Modal/行内（明确）
- 异步完成 → Notification（PC）
- 需输入 → Modal/Drawer
- 辅助说明 → Tooltip

---

## 4. 频率约束

- 同页同时 ≤ 1 个加载动画
- Toast 不堆叠（合并/排队）
- 避免连续多个弹窗

---

## 5. 规则

- ✅ 反馈即时（< 100ms 起）
- ✅ 错误给解决方案
- ❌ 关键错误一闪而过（Toast）
- ❌ 轻提示用 Modal 打断
