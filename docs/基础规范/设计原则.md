# 设计原则

> 设计原则是整个系统的「宪法」。所有 Token、组件、页面模板都必须服从这些原则。当具体规范与原则冲突时，以原则为准。

---

## 1. 四大视觉原则（Ant Design）

| 原则 | 定义 | 设计中的应用 | 反面案例 |
|---|---|---|---|
| **亲密性 Proximity** | 相关元素靠近，形成视觉单元 | 表单项与标签间距 < 区块间距；同组操作聚拢 | 所有元素等距排列，无法区分分组 |
| **对齐 Alignment** | 元素建立视觉联系 | 统一左对齐文本基线；卡片网格对齐 | 元素随意居中/右对齐，画面零碎 |
| **对比 Contrast** | 用差异突出重点 | 主按钮实心 vs 次按钮描边；标题加粗 | 所有按钮同款样式，主操作不突出 |
| **重复 Repetition** | 一致的视觉语言贯穿全局 | 同一组件在所有页面样式一致 | 每页自定义新按钮样式 |

### 亲密性的量化规则

```
信息层级通过间距表达（见 间距与圆角.md）：
  同组内元素间距  = 8px
  同区块分组间距  = 16px
  不同区块间距    = 24px
```

### 对比的量化规则

- 主操作与次操作的视觉权重差：填充 vs 描边（或 主色 vs 中性色）
- 标题与正文字重差：Medium(500)/Semibold(600) vs Regular(400)
- 重要信息用主色 `#1677FF` 或加粗，而非仅靠字号

## 2. 四大体验原则

| 原则 | 定义 | 落地要求 |
|---|---|---|
| **清晰 Clarity** | 内容为王，界面退居幕后 | 每屏一个重点；减少装饰性元素；信息层级分明 |
| **一致 Consistency** | 内外部一致，降低学习成本 | 同功能同组件；跨平台遵循各自原生惯例 |
| **反馈 Feedback** | 每个操作即时可感知 | 操作 100ms 内反馈；加载有态；结果明确 |
| **效率 Efficiency** | 减少操作步骤 | 优先选择而非输入；提供批量与默认值 |

---

## 3. 设计价值观

| 价值观 | 说明 | 对设计的约束 |
|---|---|---|
| **自然 Natural** | 符合用户直觉 | 不发明反直觉交互；动效模拟物理规律 |
| **克制 Restraint** | 少即是多 | 单页字号 ≤ 5 种；颜色克制；阴影不过度 |
| **确定性 Certainty** | 消除随意性 | 用 Token 与组件库替代临时决策；可复用优先 |
| **包容 Inclusion** | 覆盖更多人群 | 满足 WCAG AA；支持动态字体；触控目标达标 |

---

## 4. 决策检查清单

设计评审时用以下清单快速判断是否符合原则：

- [ ] 页面是否有且只有一个视觉重点？
- [ ] 主操作是否比次操作更突出（对比原则）？
- [ ] 相关元素是否通过间距形成了分组（亲密性）？
- [ ] 所有同类组件样式是否一致（重复）？
- [ ] 元素是否对齐到统一基准线（对齐）？
- [ ] 任何操作是否在 100ms 内有反馈？
- [ ] 颜色/间距/圆角是否来自 Token，而非魔法值？
- [ ] 是否满足了 WCAG AA 对比度？
