# 声音与触感反馈

> 模块：基础规范 ｜ 适用：移动端（iOS / Android / HarmonyOS）/ H5
> 关联：动效系统、反馈机制、手势规范
> 核心：**多通道反馈（视觉+触觉+声音）降低不确定性**。但"多"不等于"滥"，过量会疲劳。

---

## 1. 反馈通道选择

| 操作类型 | 视觉 | 触觉 | 声音 |
|---|---|---|---|
| 点按按钮 | ✅ 高亮/缩放 | ✅ 轻触 | ⚪ 可选 |
| 开关切换 | ✅ 态变 | ✅ | ❌ |
| 成功提交 | ✅ Toast | ✅ 双短震 | ✅ 轻"叮" |
| 删除/危险 | ✅ 确认弹窗 | ✅ 重震 | ✅ 低沉 |
| 错误/失败 | ✅ 红字/Modal | ✅ 三连震 | ✅ 错误音 |
| 收到消息 | ✅ 角标/横幅 | ⚪ | ✅（可静音） |
| 长列表滚动 | ✅ 惯性 | ❌ | ❌ |

---

## 2. 触觉（Haptics）

| 平台 | API | 常用类型 |
|---|---|---|
| iOS | `UIImpactFeedbackGenerator` / RN `react-native-haptic-feedback` | light / medium / heavy / rigid / soft |
| Android | `Vibrator` / `HapticFeedback` | 短震(10ms) / 双击 / 长震 |
| HarmonyOS | `vibrator` 模块 | 轻 / 中 / 重 |

- **强度分级**：轻触=light(10ms)，确认=medium，危险=heavy/三连。
- **克制**：滚动、hover 不震；仅在"离散有意义"的操作震。
- **可关**：设置页提供"触感反馈"总开关，默认开。
- 微信小程序：受平台限制，依赖 `wx.vibrateShort`（仅短震），不保证强度。

---

## 3. 声音（Sound）

- **类型**：成功（上扬短音）、失败（下沉短音）、提示（中性）、消息（独特可辨识）。
- **规范**：
  - 时长 ≤ 300ms，频率清晰不刺耳（200~800Hz 区间）。
  - 用系统音效优先（iOS `UINotificationFeedback` 音随触觉），避免自录大文件。
  - 提供"声音反馈"总开关，默认开但尊重系统静音（iOS 静音键不响）。
- **场景限制**：输入法按键音、游戏音效不在此规范；业务反馈音才受控。

---

## 4. 无障碍关联

- 触觉/声音是视觉反馈的**补充**，不能替代视觉（色盲/聋人/静音场景）。
- 错误必须同时有视觉（红字/图标）+ 非视觉（震/音）至少两通道。

---

## 5. 反模式

- ❌ 滚动/悬停也震动（疲劳）
- ❌ 无总开关强制触感/声音
- ❌ 仅用声音表示错误（静音场景失效）
- ❌ 自录大体积音效拖慢首屏
- ❌ 每次点击都响（滥用）

---

## 6. 自检

- [ ] 触觉分级（轻/中/重）且克制
- [ ] 有"触感/声音"总开关
- [ ] 错误双通道（视觉+非视觉）
- [ ] 声音 ≤ 300ms、尊重静音
- [ ] 不滥用（滚动/悬停无反馈）
